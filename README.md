# 胶片档案交档

馆内用一套**档案卷**保存多部成片共用的胶片素材。交档时填写成片号并上传剪辑
CSV，系统为每个原卷建立一卷从 0 开始编号的档案卷，把新帧连续追加到卷尾，并
给出按单号可查的取帧单。

## 规则实现对照

| 需求 | 实现 |
| --- | --- |
| 填成片号、上传剪辑 CSV，每行镜头号/原卷号/起帧/帧数 | 交档页表单，CSV 全量校验后才落库 |
| 每个原卷对应一个档案卷，档案帧号从 0 起 | `reels.next_frame` 初始为 0，`archive_segments` 从 0 起铺满 |
| 已收帧沿用档案帧号，新帧连续追加到卷尾 | 覆盖索引命中的区间原地复用；未覆盖空隙只在卷尾分配 |
| 同一帧一单多次引用 / 两单并发引用只拷一次 | 覆盖索引 + `BEGIN IMMEDIATE` 单事务；并发测试覆盖 |
| 按单号查本次拷贝的原卷帧段与落点 | `/orders/<单号>` 与 `/api/orders/<单号>` 的 `copies` |
| 查每个镜头依次从档案卷取哪些帧段以拼回原帧序 | 同页 `shots[].segments`，按 `seg_index` 顺序拼接 |
| 清单与索引一同生效，失败时旧单和卷尾不变 | 单事务写入 `orders/shots/order_copies/shot_segments/archive_segments/reels`，异常整体回滚 |
| 全程按帧段核算，不逐帧展开 | 所有计算基于半开区间 `[start, start+count)`，与帧数量级无关 |

## 实拷回报（拷片核对）

保管员拷完胶片后，在**单号页**上传实拷 CSV，每行 `原卷号,档案起帧,帧数`，
声明实际拷贝完成的档案帧段。

| 需求 | 实现 |
| --- | --- |
| 每行只能确认本单安排新拷的帧，可跨相邻新拷段 | 写入前在事务内逐行校验，区间必须包含于本单 `order_copies.is_new=1` 的档案区间并集 |
| 越界或保存失败，整份回报不生效 | 解析、校验、写入同在一个 `BEGIN IMMEDIATE` 事务，任一失败整体回滚，确认范围不变 |
| 分批可乱序、重叠或同时提交，已确认取并集 | `order_confirmations` 按“单号+原卷”存规范化不重叠区间，写入时与既有并集做差集 |
| 重复上报已确认帧不增加查单记录 | 与并集重叠的部分被吸收，只插入新增区间；原始批次另存 `copy_reports/copy_report_rows` 备查 |
| 单号页和原 JSON 按镜头列出还缺的档案帧段及首拷单号 | 报告 `shots[].missing_segments`，按覆盖索引标注 `first_copy_order_no` |
| 镜头帧全部确认才标为可取片 | `shots[].ready_for_pickup` 与整单 `ready_for_pickup` |
| 沿用帧看首拷单回报，旧单无回报则未确认 | 每段档案帧由 `archive_segments.created_order_id` 的确认并集判定，与当前单号无关 |
| 核对期间可继续交档，登记不重算其他单 | 回报只写本单三张表，不触碰 `archive_segments/reels`，交档与回报用独立事务串行 |
| 查单只核对本单所需帧段，整次查询同一份已提交数据 | `get_order` 用单个只读事务快照读取，全程基于本单镜头所需档案区间 |
| 原拷贝清单与取片顺序照常可查 | `copies`、`shots[].segments` 结构保持不变 |

### 实拷 CSV 格式

```csv
原卷号,档案起帧,帧数
R001,0,120
R001,120,50
```

* 固定三列，支持常见中英文表头别名；UTF-8（含 BOM）或 GB18030 编码。
* 档案起帧、帧数为非负整数，帧数大于 0；任一行越界则整批拒绝。
* 样例见 `samples/report.csv`。

### 确认语义

* **新拷帧**：由安排该次新拷的单号自己回报确认。
* **沿用帧**：档案中已存在，由其**首拷单号**的回报确认；首拷单未回报时，
  任何沿用它的镜头都保持“待确认”。
* 镜头读取的每段档案帧都被对应首拷单确认后，该镜头才标记“可取片”；
  单内所有镜头可取片时，整单才可取片。

## 核心概念

* **原卷帧段**：CSV 中的 `[起帧, 起帧+帧数)`，半开区间。
* **档案卷尾**：`reels.next_frame`，该卷第一个尚未使用的档案帧号。
* **覆盖索引**：`archive_segments` 记录“原卷帧段 → 档案帧段”的不重叠映射。
  命中即可复用；未命中才在卷尾分配并写入。

取帧单里的每一段都是连续档案区间，按 `seg_index` 依次读取拼接即可还原该镜头
的原始帧序，无需逐帧处理。

## 本地运行

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt

python3 -m archive          # 开发服务器，默认 0.0.0.0:8000
# 打开 http://localhost:8000
```

环境变量：

* `ARCHIVE_DB`：SQLite 路径，默认 `data/archive.sqlite3`
* `SECRET_KEY`：会话密钥；未设置时会在数据库旁生成并持久化
  （`*.sqlite3.secret`），确保多 worker 共享同一密钥
* `PORT` / `HOST`：开发服务器监听地址

## Docker Compose

```bash
docker compose up --build
# http://localhost:8000
```

数据库文件位于命名卷 `archive-data`，重建容器不会丢失。生产部署请通过
`SECRET_KEY` 环境变量显式提供密钥（`docker compose` 默认值仅供本机试用）。

## 测试

```bash
python3 -m pytest -q
```

覆盖：首单从 0 分配、复用+追加、单内重复引用去重、多原卷、取帧单顺序、校验
失败回滚、事务中途异常回滚、重复单号、超大帧段（5000 万帧）不逐帧展开、随机
不变量检查，以及多线程 / 多 gunicorn worker 并发交档；实拷回报覆盖越界整批
拒绝、跨相邻新拷段、乱序/重叠/并发取并集、重复上报不新增核对记录、沿用帧跟随
首拷单回报、镜头与整单可取片判定，以及回报与交档并发互不影响。

## CSV 格式

```csv
镜头号,原卷号,起帧,帧数
S01,R001,0,120
S02,R001,100,50
```

* 固定四列，支持常见中英文表头别名；UTF-8（含 BOM）或 GB18030 编码。
* 空行忽略；支持带引号字段与 CRLF。
* 起帧、帧数为非负整数，帧数必须大于 0。
* 任一行出错则整单拒绝，页面会一次列出所有问题，档案卷不发生改动。

样例见 `samples/edit.csv`。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 交档页、按单号查询、最近交档 |
| POST | `/submit` | 交档（multipart：`order_no`、`film_no`、`csv_file`、`csrf_token`） |
| GET | `/orders/<单号>` | 单号详情页（含实拷回报表单、缺失帧段、可取片状态、回报历史） |
| POST | `/orders/<单号>/reports` | 上传一批实拷回报（multipart：`report_file`、`csrf_token`），全有或全无 |
| GET | `/reels/<原卷号>` | 档案卷覆盖索引与卷尾 |
| GET | `/api/orders/<单号>` | 单号 JSON（含 `ready_for_pickup`、`missing_segments`、确认进度、回报历史） |
| GET | `/api/reels/<原卷号>` | 档案卷 JSON |

## 表结构

* `orders`：单号、成片号、时间、行数（单号唯一）。
* `shots`：本单每个镜头行的原始帧段。
* `order_copies`：本单需要拷贝/沿用的原卷帧段与档案落点，`is_new` 区分本次
  新建还是复用（按原卷帧段合并后每个区间一行）。
* `shot_segments`：每个镜头按顺序应读取的档案帧段。
* `reels`：每原卷一卷，`next_frame` 为卷尾。
* `archive_segments`：全局覆盖索引，含触发器保证同卷内原卷帧段、档案帧段均
  不重叠且不越过卷尾；`created_order_id` 即每段档案帧的首拷单号。
* `copy_reports` / `copy_report_rows`：实拷回报的批次与原始行，作为上传留痕。
* `order_confirmations`：每单已确认档案帧段的规范化不重叠并集，含触发器
  防止同单同卷区间重叠；查单核对只读这张表，重复上报不产生新记录。
